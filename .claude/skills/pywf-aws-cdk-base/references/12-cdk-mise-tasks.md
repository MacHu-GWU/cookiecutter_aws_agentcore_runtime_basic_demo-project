# CDK mise Tasks

Seed repo: [`mise_tasks.py`](https://github.com/MacHu-GWU/cookiecutter_aws_cdk_demo-project/blob/1.0.0/cookiecutter_aws_cdk_demo/cdk/mise_tasks.py), [`mise.toml`](https://github.com/MacHu-GWU/cookiecutter_aws_cdk_demo-project/blob/1.0.0/mise.toml).

---

## 1. Generated, never hand edited

`mise run gen-env-tasks` rewrites the block between `# <env-tasks>` and `# </env-tasks>` in `mise.toml` from the entries of `StackCtxEnum` (`10-cdk-stack-enums.md`) and the members of `EnvNameEnum` (`03-env.md`). Rerun it after changing either. A unit test fails while the block is stale.

---

## 2. The tasks

| Task | cdk command | Calls AWS |
| :--- | :--- | :--- |
| `cdk-synth-<env>-<x>-stack` / `-all` | `cdk synth` | no |
| `cdk-plan-<env>-<x>-stack` / `-all` | `cdk diff --method auto` | reads |
| `cdk-up-<env>-<x>-stack` / `-all` | `cdk deploy --require-approval never` | changes |
| `cdk-down-<env>-<x>-stack` / `-all` | `cdk destroy --force` | changes |

- Each task runs one plain cdk command in `cdk/`, with `ENV_NAME=<env>`. A `-stack` task selects the stack by its name with `--exclusively`; an `-all` task uses `--all` and lets cdk order the stacks.
- Every task but synth passes `--profile {{env.AWS_PROFILE_FOR_<ENV>}}` (`06-boto-session.md`) and stops if the variable is unset.
- **Before the command, every task prints the CloudFormation console URL** (`config.cft_stack_url_<x>`) of each stack it acts on, then the command line.

This project adds, per environment, in the same block:

| Task | Runs | Calls AWS |
| :--- | :--- | :--- |
| `config-deploy-<env>` / `config-deploy-all` | `one.deploy_config()`: the whole config as JSON to SSM `config.ssm_param_name_config`, a `SecureString`, only if it changed | changes |
| `config-delete-<env>` / `config-delete-all` | `one.delete_config()` | changes |
| `ac-deploy-<env>` | check that the `agentcore_deps` policy and the config exist, `ac-gen` for `<env>`, check the wheels, then `agentcore deploy --target <env>` | changes |
| `ac-down-<env>` | `agentcore deploy --target <env> --yes` of an empty generated project (destroys its runtimes), then `ac-gen` again | changes |
| `ac-chain-up-<env>` | `config-deploy-<env>` → `cdk-up-<env>-agentcore-deps-stack` → `ac-deploy-<env>`, in order | changes |
| `ac-chain-down-<env>` | after a confirmation: `ac-down-<env>` → `cdk-down-<env>-agentcore-deps-stack` → `config-delete-<env>` | changes |

Every generated task first prints `>>> <task>: <what it does>`; a chain task first prints its whole chain, then runs its steps with `{ task = ... }` entries, which stop at the first failure.

---

## 3. `print-cdk-stack-urls`

`mise run print-cdk-stack-urls` prints the console URL of every stack in every environment, without calling AWS. An environment whose config fails to load (such as one without its secret file) prints an error line, and the others still print.

---

## 4. The user's yes

- Run freely: `synth`, `plan`, `cdk ls`, `gen-env-tasks`, `print-cdk-stack-urls`.
- `up`, `down`, `config-deploy`, `config-delete`, `ac-deploy`, `ac-down`, and the `ac-chain-*` tasks change AWS: run them only after the user's yes, one environment per yes. `mise run int-test` reads deployed stacks; ask before relying on it.
- To run one stack yourself, call the cdk CLI from `cdk/`: `ENV_NAME=<env> mise exec -- cdk diff <stack_name> --exclusively --profile "$AWS_PROFILE_FOR_<ENV>"`. For a cdk option, see the `aws-cdk-cli-ref` skill.
